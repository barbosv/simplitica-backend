# Owned numbering and immutable device reservations

This internal Workers/D1 component supports upcoming document creation and the later verified native import/sync path. It introduces no public endpoint, model-selected owner, standalone SQL executor, ready toggle or device-proof substitute. Production/default migrations/bindings remain unchanged. Authoring still requires the reviewed current cloud authority/ready/fresh-paid guard. Native callers must later add their separately verified native proof/counter/challenge/domain guards before executing any plan.

Use one owner-global monotonic safe-integer next index and generation. Store current prefix/pad format and immutable per-reservation format snapshots. Reserve exactly20 consecutive numeric indices per active authenticated owned device; never reclaim any reserved index after disconnect or deletion. All numbering-changing batches increment generation, including server allocation, reservation, consumption and preserved-number import. A pre-read occupancy decision is valid only with its matching generation CAS in the committing batch. Never reset or decrement next index/generation.

Every formatted issued number is unique per owner, and one document has one issued number. Unissued reservation ranges are occupied too. A server allocation or historical import must exclude all reservations, including other prefixes/formats that produce the same string (prefix1/index10 and blank/index110 both produce110). A reserved native issuance must prove exact owner/device/reservation membership and immutable formatting. Disconnected reservations remain occupied but their device cannot newly consume them. Preserve historical numbers exactly and return an explicit collision instead of renumbering.

Source-internal planners return additional bound predicates/statements; they never execute a partial numbering mutation by themselves. Callers combine them with entity/idempotency/feed and verified authority in one checked D1 batch. Failed receipt/revision/domain writes roll numbering back. Conflict recovery may recompute a counter choice only if user intent and explicit expected entity revisions remain unchanged; it cannot silently rebase an edit. Bound retries and candidate scanning; exhausted space is explicit, never wraps.

Initial verified native import will create/seed numbering before records become ready, securing all historical issued strings and max historical/preferences/UserDefaults next hints. This component has no public initializer or ready setter; tests insert explicit internal fixtures. Pending native import implementation is a release dependency, not a reason to invent a cloud bypass. Offline clients that exhaust their20 block retain unnumbered drafts and require reconnect before numbered PDF/send.
