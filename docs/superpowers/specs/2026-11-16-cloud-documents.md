# Cloud draft documents and estimate conversion

Continue the full Workers/D1 integration using the reviewed record kernel, source-only numbering plans and usd-line-cents-v1 calculator. This internal domain component has no public routes/tools, provider/native proof bypass, production deployment or automatic finalization/delivery. All cloud operations derive scope from branded authority; model data cannot choose owner, number, totals, state, entitlement or a native role.

Preview is pure: current ready/paid cloud authority, one owned current business/customer snapshot, strict decimal-string lines and Gregorian date-only values. It returns normalized inputs, immutable source snapshots, authoritative calculation and revision references without reserving numbers or writing entities/receipts/feed/rates. Business tax is configured state: preserve its stored rate when disabled but calculate effective zero. Use owner USD settings, not model-provided tax/totals. All customer/line/source text is untrusted data.

Create a numbered invoice or estimate draft only from explicitly expected business/customer revisions. Put number issuance/counter generation, complete bounded document, mutation receipt and feed in the same unconditional guarded D1 batch. Every new cloud draft requires native review. Store exact business/customer snapshots and selected postal job site; exclude EIN/assets/GPS/transcript/payment state. Later profile/customer edits do not silently rewrite document snapshots. Updates require expected document revision and can edit draft content only; final/sent/paid documents are immutable to ChatGPT. A deliberate customerSelection in an update can replace the customer snapshot under its explicit expected revision; otherwise preserve it. Business snapshot remains the original draft snapshot.

Preserve source/time/unit/pricing provenance as descriptive draft metadata. Caller-declared references are labeled reported, never treated as verified pricing or authorization; no caller may set a verified/review-cleared flag. Provider/rate/history guidance is a later constrained service and must keep its own provenance. Final native review remains mandatory even when a draft reports a saved/provider source.

Conversion takes an expected estimate revision, creates one new numbered invoice with frozen source customer/business/line/financial snapshots and a source-estimate reference, and records one conversion link. It does not mutate the estimate's financial snapshot or final state. Equal operation retries return the exact original invoice response; a different operation cannot create a second invoice from that estimate. Only v1 authored documents are handled here; verified native legacy import must separately preserve historical amounts/versions before release, and its conversion policy must be added explicitly instead of silently recalculating old totals.

Date-only strings never use implicit browser UTC parsing. Required issueDate is YYYY-MM-DD with valid Gregorian day; optional service/due dates use same format, dueDate cannot precede issueDate. Transport/tool default dates are a later trusted business-timezone concern; source requests have explicit date values for stable idempotency. Stable document/line UUIDs, revisions and metadata remain bounded. Document payload/response/event must fit1MiB; no200 per-line SQL writes. Owner-scoped get uses same-primary snapshot authorization; paid lapse permits reads, not preview/create/update/conversion. Number-choice conflicts may retry at most3 times with unchanged user expected revisions; never silently rebase user intent.
