# Owned Cloud Records Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development task-by-task with independent review. Continue directly into document/numbering/MCP/native work afterward; no milestone approval pauses. The preceding calculation plan's single raw-JSON fix must finish before editing shared calculation helpers.

**Goal:** Persist owned business/customer/rate records with transaction-time authoring checks, exact mutation receipts and a durable change feed.

**Architecture:** A private checked D1 mutation kernel combines current cloud authority, fresh verified entitlement, expected record conditions, entity changes, receipt and feed in one batch. Typed repositories build static owner-scoped statements; no SQL is accepted from a request. Native verified import/device authorization will reuse the private planning pieces later, without a model-selected bypass.

**Tech Stack:** Existing TypeScript, jose, Workers/D1 and workerd tests; opt-in migration0003, no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-15-cloud-records.md`, calculation contract and approved Workers/D1 adaptation.

## Global Constraints

- No production routes/default migrations/bindings/deployment/merge, PostgreSQL/Cloud Run or legacy ownership backfill. New code remains internal until live provider/native/purchase gates pass.
- Owner/business/client/epoch/namespace derive from verified authority, never model parameters. Every write guards current active owned device/connection, ready data and fresh active/trial/grace entitlement in the same batch.
- Decimal-string money only; current versioned calculator is authoritative. No raw record/proof/token/SQL error logging.
- Idempotency, revisions and feed updates are atomic. Existing checked guard is unconditional VALUES/CASE; zero affected rows are not a failed transaction.
- Native local-only fields and finalized legacy snapshots remain untouched. Saved-rate creation is explicit; previews/document creation must not save rates automatically.

## Review Focus

1. Revocation, entitlement expiry/staleness or ready-state changes between planning and commit must abort all writes/receipts/feed.
2. Concurrent equal operation keys must return one exact snapshot; unequal keys/payloads and stale revisions must leave no orphan entity/feed rows.
3. Data read/ID search, replay and feed pagination must not cross owner scope or accept fabricated JSON authority.
4. Feed pruning, empty pages and rolled-back writers must not reuse committed sequence values or silently accept an obsolete cursor.
5. Signed entitlement ordering must not let an old or equal-conflicting provider fact revive a revoked capability; internal fixture inputs are not real proof.

## Task 1 — Authority, entitlement, atomic journal and feed kernel

**Files:** create `migrations/chatgpt-d1/0003_cloud_records.sql`, `src/chatgpt/records/types.ts`, `authority.ts`, `kernel.ts`, `entitlements.ts`, `test/worker/cloud-record-kernel.test.ts`, `test/worker/cloud-entitlements.test.ts`. Split small helpers when necessary; no unrelated refactoring.

**Schema:** owner-scoped `cloud_record_state` (businessId, importing/ready phase, random UUID sync epoch, head/floor safe integers), `cloud_entitlements` (same-owner app/environment/lineage, state, expiresAt/graceExpiresAt, signedAt, checkedAt), `cloud_mutation_receipts` (owner+operationKey PK, kind/requestHash/exact response JSON/committedAt), `cloud_record_feed` (AUTOINCREMENT sequence, owner, kind/id/revision/payload/payload_bytes/tombstone/time), and business/customer/rate tables consumed by Task2. Business one per owner/business; other tables PK(owner,id), revision and timestamps, JSON payload and normalized search text, soft deletion. Add only a necessary unique superkey index on existing purchase lineage for a same-owner composite FK; do not reinterpret prior billing. Revisions/times/sequences are bounded nonnegative/positive safe integers as appropriate; JSON is valid, money stays inside decimal-string JSON.

**Interfaces:**
- `createCloudRecordAuthorizer(db,{authorizationNamespace,keys?,now?})` wraps the existing signed cloud token authorizer, returning immutable `CloudRecordAuthority|null` with a private unforgeable marker plus its existing owner/business/epoch/namespace scalars. Do not duplicate JWT validation; namespace remains external trusted configuration. Kernel rejects fabricated JSON authority before D1.
- `createCloudRecordKernel(db,{authorizationNamespace,now?})` exposes `authorizeRead(authority)`, `authorizeAuthoring(authority)`, `readFeed(authority,cursor:{epoch:string;after:number},limit:number)` (1–100), and `commit(authority,command,build)` for source-internal repository use. Fixed client is existing CLOUD_CLIENT_ID. `command={operationKey:string;kind:string;request:JsonValue}`; key ASCII `[A-Za-z0-9:_-]{1,128}`, kind source-fixed bounded label. Canonical request hash includes kind+validated normalized request, sorted JSON object keys, safe integer metadata, strings and other JSON primitives; no credential epoch/generated ID/time. Reject unsupported/cyclic/oversized data with fixed errors; no caller SQL.
- `build(at:number):MutationPlan` is synchronous trusted code after asynchronous record planning. Plan has an additional SQL predicate with bound values, prepared entity statements, 1–10 validated feed events and exact JSON response. SQL predicates/statements are internal source artifacts, not wire fields. Kernel builds the unconditional authorization+additional-condition guard itself, applies statements/events/receipt/head and removes guard in one batch. Bound response/request/event payload sizes at1MiB; use fixed normalized errors. Resample trusted clock immediately before building/submitting. No external I/O between time sample and batch. Equal committed receipt may be returned only after current authoring authority is rechecked; failed SQL cannot imply success without a matching receipt.
- `RecordError.code/message`: `invalid_input`, `not_authorized`, `not_ready`, `entitlement_required`, `revision_conflict`, `operation_conflict`, `not_found`, `resync_required`, `storage_unavailable`, `invalid_configuration`. SQL/provider error text never escapes. Post-rollback state may conservatively classify a race; it must not claim an uncommitted mutation succeeded.
- `initializeVerifiedOwnerRecords(db,owner,deviceKeyId)` is internal, already-verified native enrollment input only. Guard existing owner/business/active owned device; idempotently create importing state with UUID epoch/head0/floor0, preserving existing state on retry. It grants no paid eligibility/ready status. No public ready-state method or route in this task; fixtures set ready explicitly to represent the future verified import completion.
- `applyVerifiedEntitlement(db,owner,fact,now)` is internal verified-Apple-service input only. `fact={appSlug:"simpli-invoice",environment:"Sandbox"|"Production",originalTransactionId,state:"active"|"trial"|"grace"|"billing_retry"|"lapsed"|"revoked"|"unknown",expiresAt:number|null,graceExpiresAt:number|null,signedAt:number,checkedAt:number}`. Same-owner lineage FK+guard, valid bounded timestamps, checkedAt not future. Older signedAt/checkedAt ignored, equal signedAt inconsistent status/expiry conflicts, identical may refresh checkedAt. Authoring requires checkedAt<=now and >=now-300000 and current active/trial expiry or grace expiry>now. Other states deny. No caller-supplied fact at any HTTP endpoint.
- Feed results carry changes, nextCursor, head and hasMore from one consistent primary state/page snapshot. Enforce an aggregate page budget1,500,000 UTF8 bytes with bounded metadata overhead (a maximum1MiB event must fit); select metadata/window byte totals before projecting large payloads, so limit100 cannot fetch100MiB past D1 result limits. Persist/check payload_bytes against SQL byte length. Test multiple large events, pagination, hasMore and exact cursor continuity without dropping a too-large first event. No unbounded IN lists beyond100 bound parameters. Epoch mismatch or below-floor cursor throws resync_required; future cursor/invalid limit invalid_input; tombstones are returned. Internal `pruneOwnerFeed(db,ownerId,expectedEpoch,through)` atomically raises floor/deletes only that owner's rows, preserving persisted head/AUTOINCREMENT. No public pruning tool or automatic job.

## Task 2 — Business, customer and explicit rate repository

**Files:** create `src/chatgpt/records/validation.ts`, `repository.ts`, `test/worker/cloud-records.test.ts`; extend existing calculator only with a small shared scalar tax normalizer if necessary to prevent duplicate numeric validation. No numeric behavior change. Use Task1 schema/kernel.

**Interfaces:**
- `createCloudRecordRepository(db,{authorizationNamespace,now?})` exposes `getBusinessContext`, `putBusinessProfile`, `searchCustomers`, `getCustomer`, `createCustomer`, `updateCustomer`, `deleteCustomer`, `searchSavedRates`, `getSavedRate`, `putSavedRate`, `deleteSavedRate`, taking derived CloudRecordAuthority, never owner IDs in model params. Mutators take operationKey and expectedRevision (0 for create/upsert missing, >=1 otherwise); createCustomer may accept an optional stable UUID, otherwise generate it only after normalized request hashing/receipt lookup. Reads remain allowed with lapsed subscription; mutations require kernel authoring checks.
- Return `VersionedRecord<T>={id:string;revision:number;createdAt:number;updatedAt:number;deletedAt:number|null;value:T}`. IDs canonical lowercase UUID; every predicate/write scoped to derived owner and business. A deleted record is not silently recreated/overwritten. Deletes keep tombstones/revision, publish minimal delete feed payload. Stable searches take `{query:string,afterId?:string,limit:number}` (query<=200 UTF8 bytes, limit1–100), use normalized literal substring indexing and stable UUID pagination, never raw SQL/LIKE patterns.
- Strict value shapes from spec: business profile(contact/address/tax/terms/timezone), customer(contact/billing/saved postal job sites), rate(title/detail/defaultQuantity/unitPrice/unit/kind). Bounds: names/titles<=256 UTF8 bytes, individual address/site strings<=1024, address arrays<=10, sites<=20, optional detail/paymentTerms<=2048, phone<=64/email<=254/website<=2048, unit null or one of each/hour/day/sq_ft/linear_ft/cu_yd/lb/gal/job, kinds native service/labor/materials/fee/other. Required display names trimmed and nonempty; optional empty contacts->null; preserve meaningful display text, reject malformed Unicode/control characters inappropriate to single-line contact fields. Tax rate normalized/shared, enabled=false forces effective0; rate quantity/price normalized by actual single-line shared calculation, not duplicated floating math. Timezone must be an Intl-valid IANA identifier and retained canonically; no network validation. No tax ID/EIN, asset/GPS/transcript/payment fields accepted.
- `putSavedRate` additionally requires `explicitUserRequest:true`; it is not called by preview/document creation, and later MCP toolset exposes rate reads only. Missing historical unit remains null. Native import will use separately verified device authority/plans later, not caller-selected bypass here.
